# Lazy Learning Method（方法源流）

> 來源：YouTube 影片 [`qQZNJaP5Ej4`](https://www.youtube.com/watch?v=qQZNJaP5Ej4)（2026-08-26 從逐字稿提取；影片已標記 unavailable，此文件為存檔蒸餾）。原脈絡是 cybersecurity 自學，方法是通用的。片中段的工具業配（Hackify）與方法無關，已剝除。

## 核心命題

Hacking is not about knowing more. It is about deciding faster.
駭客能力不在知道多少，在決策多快。多數初學者比專業人士更努力、更多工具、更多筆記，卻在真實目標前凍住——因為他們優化了消費，沒有優化「失敗到洞察」的迴圈。

**Lazy 的真義**：lazy ≠ 不認真，lazy = 移除一切摩擦。精確勝過蠻力，回饋勝過苦磨。

## 八條鐵律

1. **Never learn unless a real problem forces you to.**
   沒有真實問題逼你，就不學。不預修課程、不考照先行、無上下文的理論不碰。
2. **Start with a real target, not a curriculum.**
   從真實目標開始，不是課綱。一次一個目標；自信是行動的結果，不是前提。
3. **The loop is everything.**
   定向 → 輕偵察 → 假設 → 小步測試 → 觀察 → 調整假設。想法到測試的速度＝學習速度；任何拖慢迴圈的東西都該刪。
4. **Research exactly what blocked you. Then stop.**
   研究只研究擋路的那件事：精確症狀、確切錯誤訊息。能再測就停。過度研究感覺安全，但安全感不長直覺——行動才長。
5. **Ask what assumption the exploit relies on before copying it.**
   抄任何招之前先問「它依賴什麼假設」。抄而不懂會繞過迴圈，殺死學習。失敗時調整的是假設，不是指令。
6. **Write conclusions, not command graveyards.**
   筆記寫結論：為何成功、為何失敗、哪個假設變了。指令清單感覺有產出但無法遷移。
7. **End every session deliberately.**
   刻意收尾：要嘛拿下一勝，要嘛寫下一條明確的阻塞問題。阻塞問題就是下一場的入口。永遠不在挫折中隨機中斷。
8. **Discomfort is the signal that learning is happening.**
   困惑與不足感＝學習正在發生的訊號。多數人在這裡逃回課程的懷抱。

## 配套紀律

- **工具極簡**：每加一個新工具都重置學習曲線。早期深度壓過廣度——小工具集反覆用，熟悉度複利，直覺開始預測輸出。
- **速度即槓桿**：迴圈裡最貴的成本是「想法→測試」之間的一切摩擦。
